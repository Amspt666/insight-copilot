# 架构决策记录

## ADR-001：企业试点只读

决策：只读是系统边界，不是前端提示。应用、数据库账号、网络和源端接口共同执行。

原因：项目价值是分析和解释；写操作会把模型理解错误直接变成企业数据事故，也不属于本试点价值证明范围。

## ADR-002：企业输入优先于通用推断

决策：企业语义、血缘、权限、质量和验收规则必须由企业提供或确认。平台提供模板、导入器、校验器和检索机制。

原因：不同企业对销售额、客户、应收、月末和有效期的定义不同，通用行业知识只能做候选，不能做事实。

## ADR-003：权威血缘表进入元数据检索

决策：企业批准的血缘关系查询表或治理平台输出作为关系检索的权威输入，保留来源版本、边 ID、基数、粒度和审批状态。

原因：表名相似度和模型猜测无法证明 Join 路径；血缘表能够把企业确认的关系变成可追溯输入。数据库自动发现和模型召回只能补充候选，不能覆盖权威结果。

## ADR-004：架构包可以独立于企业部署

决策：v1.2交付架构、契约、模板、示例流程和验收方法，不把“已在某企业生产部署”作为完成条件。

原因：项目价值是展示完整解决思路，企业实施需要企业自身系统、权限、治理和业务负责人参与。架构必须让实施方能够按输入契约落地。
