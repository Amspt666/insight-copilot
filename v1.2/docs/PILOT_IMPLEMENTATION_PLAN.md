# 企业只读试点实施计划

这个计划面向“提供架构和解决思路”的交付方式。平台可以完成模板、参考适配器和演示，但企业事实必须由企业确认。

## 阶段1：共同理解

企业确定业务域、试点用户、系统版本、公司范围、只读目标、禁止事项和验收人。输出试点范围表、责任矩阵和问题清单。

## 阶段2：企业输入收集

企业提交语义指标、术语、澄清规则、数据字典、血缘关系表、Join/粒度说明、权限矩阵、质量规则、标准报表、刷新时间和脱敏样例。平台做格式和一致性检查，标注缺失但不替企业猜测。

## 阶段3：目录与血缘快照

平台导入企业批准的目录和血缘，生成版本化快照。企业数据治理负责人确认关键指标的字段绑定、关联路径、基数和有效期。冲突路径不进入查询。

## 阶段4：只读执行边界

企业提供只读账号/接口和安全视图。企业基础设施验证数据库权限、网络出口、行列权限、RLS/CLS、查询预算和日志保留。平台提供只读校验和拒绝用例。

## 阶段5：题集与对账

企业使用真实但脱敏问题创建验收集，每题包含期望计划、参考结果和证据要求。平台运行意图、检索、Join、结果、权限和解释评估。财务负责人对金额口径签字，安全负责人对只读边界签字。

## 阶段6：架构交付

交付架构图、企业输入契约、目录快照、权限矩阵、只读连接规范、验收报告、运行手册、变更流程和已知限制。是否由企业自行部署不改变这些交付物的完整性。
