# 只读安全与治理

## 只读原则

企业试点系统只查询批准的数据源。它可以读取、聚合、比较、解释和导出已授权数据，但不能改变源系统或治理目录中的业务事实。

明确禁止：过账、清账、反清账、支付、修改客户、修改配置、建表、修改权限、写入结果回源、写入型 RFC/BAPI/OData、写入型存储过程、文件访问和网络函数。

## 权限执行顺序

1. 认证用户和租户。
2. 加载企业批准的公司/组织/客户/列范围。
3. 用权限过滤业务目录和血缘检索结果。
4. 将权限条件注入逻辑计划，由服务端锁定。
5. 编译为授权视图查询或通过企业只读 API。
6. 执行器和数据库连接同时检查只读能力。
7. 导出前再次检查行列权限和敏感信息策略。

模型看不到数据库密码，也不能提交 `tenant_id`、用户 ID、权限策略或安全视图之外的对象。

## 审计记录

每次查询记录查询 ID、用户/租户摘要、语义版本、目录快照、血缘边 ID、权限策略版本、逻辑计划、SQL 哈希、参数脱敏摘要、源快照水位、执行状态、结果校验和证据引用。日志不记录思维链、密钥或未经脱敏的敏感字段。

## 事故处理

发现写权限、权限绕过、血缘冲突、语义版本不匹配或质量规则失败时，立即阻断查询并保留诊断。不得以模型修复绕过治理阻断，企业安全负责人决定恢复条件。
