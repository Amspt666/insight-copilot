# v1.1 实施计划

**目标：** 独立的 SAP 风格应收与回款 Demo，DeepSeek 理解问题，受约束查询计划经程序编译、只读执行，答案附证据。

**约束：** 所有新增文件位于 `v1.1/`；复用环境配置但不复制密钥；用户自行测试，本轮不运行测试、模型请求或浏览器验收；Git 操作由用户后续处理。依据已经讨论并授权执行的方案直接实现。

**技术：** Python 3.10+、FastAPI、Pydantic 2、SQLite、sqlglot、requests、原生 HTML/CSS/JavaScript。SQLite 仅承担可携带的演示数据库；不宣称兼容 SAP HANA SQL。

## 文件与工作顺序

1. `app/config.py`、`app/models.py`：配置优先级、严格计划契约、范围校验。
2. `data/semantic.json`、`scripts/generate_data.py`：指标、复合键、关联规则，固定种子生成双分录凭证与独立核销事件。
3. `app/semantic.py`、`app/planner.py`、`app/llm.py`：检索、DeepSeek 结构化计划、一次格式修正、实体解析与能力边界。
4. `app/compiler.py`、`app/database.py`：允许的指标模板、参数化 SQL、AST 白名单、只读与超时、结果校验。
5. `app/evidence.py`、`app/pipeline.py`：证据标识、确定性派生计算、模型选择证据、受控表达、完整阶段轨迹。
6. `app/main.py`、`web/`、启动脚本：API、财务问答、澄清续问、指标目录、证据/SQL/计划面板、CSV 导出与图表。
7. `docs/TEST_PLAN.md`、`docs/V1_2_ROADMAP.md`、`README.md`：可执行的人工/API/财务核对计划及企业级建设路线。

## 设计约束

- 模拟范围：2 公司、50 客户、2025-01-01 至 2026-06-30，演示时钟 2026-07-01。
- `BKPF/BSEG` 的凭证键包含 `MANDT/BUKRS/GJAHR/BELNR`，明细另含 `BUZEI`。
- 自定义 `ZAR_APPLICATION` 显式标记为 Demo 核销事件，不冒充 SAP 原生表。按事件日期重建历史未结余额。
- 物理金额列使用整数分；人民币和美元分别计算，禁止隐式汇率折算与混合币种汇总。
- 支持余额、逾期、账龄、期间回款、余额变化；不支持收入确认、利润、预测及无证据的原因推断。
- 计划只能选择注册指标/维度；前端不提供任意 SQL 接口。编译器固定关联，所有业务过滤值绑定参数。
- 模型解释只允许选择既有证据并排序；最终业务句子由证据渲染。此版本明确不输出自由因果分析。
- 模型缺失/错误不得伪造成功。v1.1 所有查询都必须经过 DeepSeek；结构化计划仅作为内部契约，不对用户提供无模型入口。

## 人工审查重点

跨期部分核销、复合键碰撞、借贷方向、多币种、零/空结果、并列排名、未知客户、模型格式错、越范围请求、截断结果误当总体、CSV 公式注入、超时、错误信息泄露。
